Ты работаешь с личным академическим Obsidian-хранилищем ObsiNotes (медицина + биоинформатика/метагеномика). Тебе дают список путей к заметкам (относительно корня хранилища, например `Notes/DADA2.md`). Твоя задача — для каждой заметки из списка заполнить пустое поле `summary` в YAML-frontmatter.

## Формат frontmatter

Каждая заметка начинается с блока между `---`:

```yaml
---
aliases: []
date: 23-06-2026
dg-publish: false
parent:
summary:
tags: []
type: 📄note
---
```

Тебя интересует только строка `summary:`. Остальные поля (aliases, date, dg-publish, parent, tags, type, emoji-метатеги вроде `💻Bioinfo`, `🦠Metagenomics` и т.д.) — **не трогай**.

## Алгоритм на каждую заметку

1. Прочитай файл (`Read`).
2. Проверь frontmatter: если `summary:` уже содержит текст — **пропусти файл**, ничего не меняй.
3. Если `summary:` пустое — прочитай тело заметки (заголовки, ключевые абзацы, списки, ссылки) и пойми, о чём заметка.
4. Сформулируй краткое summary **на русском языке**, в стиле остальных заметок хранилища:
   - Одно предложение (реже — два коротких), примерно 8–25 слов.
   - Пиши по существу: что это за объект/метод/понятие и его ключевая суть или применение — без вводных фраз вроде "Эта заметка о...".
   - Можно использовать wiki-ссылки `[[Название заметки]]` на связанные понятия, если это уместно (как это делается в теле заметок хранилища), но не обязательно.
   - Примеры существующего стиля (для калибровки тона и длины, не копировать буквально):
     - `Инструмент для удаления контаминирующих ридов хозяина из метагеномных данных`
     - `Биологическая системная база данных метаболических путей и функций генов`
     - `Алгоритм [[Деконволюция bulkRNAseq]] — реконструкция микроокружения опухоли с помощью объемного РНК-секвенирования и алгоритма машинного обучения`
5. Запиши summary через `Edit`, заменив ровно строку `summary:` (пустую) на `summary: <текст>`.
   - Если текст summary содержит символ `:` за которым идёт пробел, либо начинается с спецсимвола YAML (`*`, `&`, `[`, `]`, `{`, `}`, `#`, `|`, `>`, `'`, `"`, `%`, `@`, `` ` ``), заверни всё значение в двойные кавычки и экранируй внутренние `"` как `\"`.
   - Во всех остальных случаях пиши без кавычек, как в примерах выше.
   - Не меняй ничего больше в файле — ни другие поля frontmatter, ни тело заметки.

## Обработка проблемных случаев

- Если заметка почти пустая (нет содержательного текста, только заголовок/заглушка) — напиши короткое summary по названию заметки и доступному контексту (не пропускай файл только из-за скудности содержимого).
- Если файл не найден или не открывается — зафиксируй это в финальном отчёте, не прерывай обработку остальных файлов.
- Если `summary:` уже заполнено — просто пропусти, отметь в отчёте как "уже заполнено".

## В конце работы

Верни короткий отчёт (не длиннее списка): сколько заметок обработано, сколько пропущено (уже было summary), список файлов с ошибками если такие есть.
