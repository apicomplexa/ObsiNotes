# Генерация схем через Python → SVG — метод и грабли

Метод, отработанный на схемах из [[bariatric-routing-moc]]. Переиспользуем для любых
схем с кириллицей, где нужна воспроизводимость и правка текстов без графического
редактора.

## Подход

Python формирует SVG-разметку строками, `cairosvg` растрирует в PNG и PDF.
Промежуточного графического редактора нет; библиотеки диаграмм (Graphviz, Mermaid,
matplotlib) тоже не используются.

**Почему не готовая библиотека.** Graphviz и Mermaid хорошо раскладывают графы, но плохо
управляются в мелочах: монохром без декора, точный кегль, таблично выровненные колонки,
комбинация «блок + боковая аннотация». Свои примитивы оказались дешевле.

**Почему не SVG руками.** ~500 строк Python на 7 схем против тысяч строк разметки
с координатами; любая правка формулировки потребовала бы пересчёта всей колонки.

Структура: низкоуровневые `rect()`, `arrow()`, `poly()`, `txt()` возвращают строки
разметки; функция схемы склеивает их в буфер; обёртка `svg()` добавляет заголовок,
маркеры стрелок и вызывает растеризацию.

## Главная грабля: ширина кириллицы

Первая версия оценивала ширину строки как «символов × 0,52 × кегль». Реальная средняя
ширина кириллицы в DejaVu Sans — **около 0,635**. Недооценка в 22 % ставила переносы
слишком поздно, и текст вылезал за границы блоков в шести схемах из семи.

Вывод общего характера: **оценочные коэффициенты ширины для кириллицы не работают,
нужны фактические метрики шрифта.**

```python
from PIL import ImageFont

def tw(s, fs, bold=False, ital=False):
    # шрифт открыт один раз при кегле 100, дальше линейный пересчёт
    return _f(bold, ital).getlength(s) * fs / 100.0
```

На этом построены `wrapw()` — перенос по фактической ширине — и `fitted()`.

## Автоподгонка

`fitted(x, y, w, h, items)` получает прямоугольник и список текстовых элементов,
переносит их по фактической внутренней ширине, а если суммарная высота не влезает —
циклически умножает кегль на 0,95 до попадания (нижний предел `minscale=0.55`).
Высоты блоков и размер полотна считаются от содержимого через `need_h()`, поэтому
в коде **нет ни одной вручную подобранной вертикальной координаты**.

Практическое следствие: тексты правятся в списках в начале функций схем, геометрия
пересчитывается сама.

## Валидатор вместо визуального осмотра

Отдельный скрипт разбирает готовый SVG через `xml.etree`, пересчитывает габариты каждой
надписи теми же метриками и ищет три класса дефектов:

1. текст выходит за пределы полотна;
2. текст выходит за границы своего (наименьшего охватывающего) `<rect>`;
3. надписи накладываются друг на друга.

На старой версии — **69 нарушений**, на новой — **0**. Отдельная проверка показала,
что и сами блоки нигде не пересекаются.

Это оказалось важнее, чем казалось: в той сессии просмотр изображений перестал отвечать,
и без валидатора гарантировать результат было бы нечем. Геометрическая проверка надёжнее
глаза по части «текст в границах» — но композицию всё равно смотреть глазами.

## Воспроизводимость

Контейнер между задачами сбрасывался, рабочие скрипты пропадали. Код восстанавливался
и проверялся против ранее выданных SVG: все 7 файлов совпали по sha256 **побайтово**,
растр 4000 px тоже. Хеши зафиксированы в `checksums.sha256`, сверка — `make verify`.

Практика на будущее: **фиксировать эталонные хеши сразу** — это единственный способ
доказать, что переданный код даёт те же артефакты, а не «примерно такие же».

## Репозиторий

`bariatric-route-diagrams.zip`, 1,4 МБ, 16 файлов.

```
src/diagrams.py     примитивы, движок автоподгонки, 7 функций схем
src/validate.py     геометрическая проверка SVG
src/export.py       экспорт PNG 4000 px, PDF, SVG, сборка архива
fonts/              DejaVu Sans (4 начертания) + лицензия
checksums.sha256    эталонные хеши
```

```bash
pip install -r requirements.txt
python3 src/diagrams.py     # → out/svg, out/png
python3 src/validate.py     # 0 = дефектов нет
python3 src/export.py       # → dist/*.zip
# или make all / make export / make verify / make clean
```

## Подводные камни при переносе на другую машину

- **cairosvg берёт шрифт по имени через fontconfig, а не из `fonts/`.** Папка `fonts/`
  нужна для *измерения* строк. Если DejaVu Sans не установлен в системе, SVG останутся
  правильными, а PNG и PDF отрисуются подменным шрифтом и разъедутся.
  Лечится: `sudo apt install fonts-dejavu-core`.
- В SVG шрифт указан по имени и не внедрён — для правки в Inkscape на чужой машине
  DejaVu Sans тоже должен быть установлен.
- Растровый вывод зависит от версии cairo: для PNG/PDF гарантируется визуальная,
  а не побайтовая идентичность. Побайтово сверяются только SVG.

## Параметры вывода

| Параметр | Значение | Где |
|---|---|---|
| Растр предпросмотра | ×2,2 от viewBox | `PREVIEW_SCALE` в `diagrams.py` |
| Растр экспорта | 4000 px по ширине (~600 dpi при 170 мм) | `TARGET_PX` в `export.py` |
| Расчётная ширина печати | 170 мм — полоса A4 при полях 25/15 мм | `PRINT_W_MM` в `export.py` |

## Если понадобится версия под слайды

Схемы рассчитаны на печатную полосу; на проекторе кегль 13–14 пунктов читается плохо.
Вариант под 16:9 с укрупнённым шрифтом и разбивкой самых плотных схем на две части —
отдельная задача, в текущем репозитории не реализована.
