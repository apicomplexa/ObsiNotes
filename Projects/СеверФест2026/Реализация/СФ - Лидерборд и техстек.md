# Лидерборд и техстек

## Статус

- Техническая система лидерборда полностью спроектирована и верифицирована.
- Опрос API подтверждён рабочим вживую; сопоставление слагов колонок проверено на реальном ответе API.
- Подготовлен полный промпт для Claude Code для сборки системы.
- Осталось: собрать и протестировать `.exe` лидерборда до мероприятия.

## Стек

- Яндекс.Формы для ввода данных организаторами, с выпадающим списком участников на основе Яндекс.Вики.
- Персональные предзаполненные URL для каждого организатора через URL-параметры.
- Бэкенд на Python + FastAPI, фронтенд — vanilla JS.
- Упаковано в единый Windows `.exe` через PyInstaller, с `config.yaml` для учётных данных.
- Яндекс.Вики хранит динамическую таблицу участников, которая подтягивается в Формы.
- Telegram используется для радио-подобной связи с кураторами на площадке.

## Yandex Forms API — заметки (верифицировано)

- Эндпоинт: `GET https://api.forms.yandex.net/v1/surveys/{survey_id}/answers`
- Требуется заголовок `X-Cloud-Org-Id` (не `X-Org-Id`), когда URL формы содержит `/cloud/`.
- Авторизация через `Authorization: OAuth <token>`.
- Таймстампы в UTC, требуют конвертации в MSK (UTC+3).
- Строки с названиями заданий содержат лишние пробелы, требуют обрезки (trim).
- Значения участников — массивы, что позволяет мультивыбор в одном ответе.

## Особенности Яндекс.Форм

- Для выпадающего списка участников используется тип вопроса "Блок Вики".
- У Wiki-источника выпадающего списка задержка кэша ~30 минут — обходится ручным обновлением и резервными слотами.

## Что фиксирует форма

Минимальный набор полей — см. [[СФ - Механика квеста]]: номер участника (`NNNN — Фамилия Имя`), какое задание. Личность организатора предзаполнена через URL-параметры, поэтому вручную её вводить не надо.
