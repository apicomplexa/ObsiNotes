
Текущая папка это Obsidian хранилище для моих учебных заметок. Твоя задача это рефакторинг хранилища, устранения неоднородности в классификации заметок.

В папке `\_.Settings/Agent Skills` лежат скилы которыми ты можешь пользоваться для упрощения работы с хранилищем

# Вот этапы которые тебе нужно выполнить




## 1. Написать дополльные Skills по __общей__ работе с Obsidian.md и плагинами



1. Синтаксис dataviewjs и поддерживаемая структура в отдельных файлах. Я начал реализовывать репозиторий для датавью на TS но не довел до ума. Оцени состояние, что уже реализовано.
2. Синтаксис Templater.
3. Работа с QuicAdd (в том числе через Obsidian CLI). Создание костомных скриптов, редактирование и запуск существующих
4. Синтаксис base
5. Работа с Excalidraw

После подумай какие скилы еще необходимы для работы с Obsidian и создай скилы для этого

## 2. Структура хранилища

1. Анатомия хранилища
     1. Методология семантической классификации заметок на основе метатегов
     2. Какие Метатеги есть в хранилище и для чего они используются
     3. Структуру папки Projects, поскольку здесь отличная от Notes классификация на основе директорий проектов. а не семантических тем в обычных заметках
  2. Индексные страницы (и папки)
  3. Файлы внешней конфигураци (\_.Settings)
  4. Наборы шаблонов для Templater (\_.Setting
  5. Наборы dataviews (\_.Settings/Templates/dобно будет на 2 этапе
  6. Наборы скриптов для QuicAdd (\_.Settings/Templates/Scripts)
  7. Используемые плагины сторонние и встроенные

## 3. Аудит хранилища

Учитывай разведанную в (2) структуру необходимо провести аудит всего хранилища: заметок, проектов, шаблонов, датавью, скриптов автоматизации, плагинов. Цели аудита:


  1. Поиск файлов, метатегов, настроек, незаполенных граф, которые нарушают текущую структуру хранилища
  2. Оценка оптимизации текущей структуры, измерения для большей точности, воспроизводимости, структурированности, облегчения доступа к информации по ментальнот чем пишут" 
   
  тебе разрешается использовать все скилы. Но тебе ЗАПЕРЕЩЕНО изменять хранилище на этом этапе

  1. Подробный отчет о состоянии хранилища в урой, и полным списком требуемых действий.
  2. Предложения по изменению структуры с обоснованиями
