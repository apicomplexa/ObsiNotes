# Отчёт 2 — Предложения по структуре ObsiNotes

> **Дата аудита**: 23-06-2026  
> **Статус**: Предложения для рассмотрения. Изменений не вносилось.

## Принципы оценки

Каждое предложение оценивается по трём критериям:
- **Точность** — насколько лучше система классифицирует заметки
- **Воспроизводимость** — насколько легко применить единый стандарт
- **Доступность** — насколько быстро найти нужную заметку

## П1. Формализовать словарь субиндексов

### Текущее состояние

Субиндексы (`tool`, `16S`, `preprocessing` и т.д.) вводятся произвольно без единого реестра. Например:
- `💻Bioinfo: [tool]` — у сотен заметок
- `💻Bioinfo: [database]` — у части заметок
- `💻Bioinfo: [fileformat]` — у части заметок

Нет документа, который бы описывал **какие субиндексы допустимы** для каждого индекса.

### Предложение

Создать файл `_.Settings/Agent Skills/REFERENCE Index Vocabulary.md` с полным словарём:

```yaml
💻Bioinfo:
  tool: Вычислительный инструмент/программа
  database: База данных
  fileformat: Формат файла
  algorithm: Алгоритм без реализации

🦠Metagenomics:
  16S: Анализ 16S рРНК
  WGS: Whole Genome Shotgun метагеномика
  preprocessing: Предобработка данных
  taxonomicProfiling: Таксономическое профилирование
  assembly: Сборка метагенома
  binning: Биннинг контигов
  ...
```

### Обоснование

- Облегчает консистентную маркировку новых заметок
- Позволяет агенту автоматически предлагать правильные теги
- Выявляет заметки с нестандартными субиндексами (аудит)

### Трудозатраты

Средние — нужно проанализировать существующие заметки и зафиксировать реальный словарь.

> [!todo] Рассмотрено
> Создание в виде статического файла не оправдано, поскольку субиндексы создаются динамически в процессе создания заметок, а не выбор из статического списка

## П2. Стандартизировать правило для создания суб-индексных страниц

### Текущее состояние

Некоторые разделы имеют папки с суб-индексными страницами (`💻Bioinfo/Программы.md`), другие нет. Нет чёткого правила "когда создавать суб-индекс".

### Предложение

Зафиксировать правило: **создавать суб-индексную страницу, когда в разделе накопилось ≥10 заметок с одним субиндексом**.

Применить немедленно к:
- `✂️GeneEdit/` — создать `Инструменты.md` (много tool-заметок по CRISPR)
- `🦠Microbiology/` — расширить (сейчас только ОКИ)
- `📊Statistic/` — создать `Тесты.md`, `Распределения.md`

### Обоснование

Суб-индексные страницы дают быстрый доступ к заметкам одной подтемы. Без правила — хаотичное создание.

## П3. Разделить `Notes/` на категориальные группы

### Текущее состояние

`Notes/` — полностью плоская структура (~278 файлов). Навигация только через индексные страницы и поиск.

### Предложение (осторожное)

Создать **два** варианта на выбор:

**Вариант А (минимальный)**: Оставить как есть. Плоская структура — сознательное решение, компенсируемое indexPage. Нет смысла менять.

**Вариант Б (умеренный)**: Выделить специальные категории в подпапки:
```
Notes/
├── _excalidraw/        # все .excalidraw.md файлы
├── _tasks/             # заметки с tag: task
└── (всё остальное)     # основная масса
```

### Рекомендация

**Вариант А**. Плоская структура хорошо работает с текущей системой индексов. Разбивка по папкам создаст путаницу с indexPage и нарушит принцип семантической классификации.

Единственное исключение: `_excalidraw/` подпапка для PNG-файлов, которые генерирует Excalidraw (они не нужны в основном списке заметок).

## П7. Документировать `parent:` поле

### Текущее состояние

Поле `parent:` в frontmatter фактически пустое у большинства заметок. Плагин **Breadcrumbs** настроен для навигации по иерархии.

### Предложение

Определить иерархии для ключевых разделов:

```
💻Bioinfo
  └── FastQC (parent: [[💻Bioinfo]])
  └── STAR (parent: [[💻Bioinfo]])
       └── STAR (параметры) (parent: [[STAR]])
```

Заполнить `parent:` у заметок, для которых иерархия очевидна (например, все инструменты — дочерние к своему методу).

### Обоснование

Breadcrumbs + parent создаёт навигационную цепочку, которая сейчас полностью неиспользована. Особенно полезно для медицинских заметок: `Гастроэнтерология → Хронический гепатит → Классификация`.

### Трудозатраты

Высокие — нужно ручное заполнение. Рекомендуется начать с одного раздела как пилот.

## П10. Создать REFERENCE-файл с описанием всех индексных правил

### Предложение

Создать `_.Settings/Agent Skills/REFERENCE Index Rules.md`:

```markdown
# Правила маркировки заметок

## 💻Bioinfo
Если заметка о вычислительном методе/инструменте — ВСЕГДА ставь этот тег.
ВСЕ ТУЛЫ маркируются Bioinfo/tool вне зависимости от другой области.

## 📊Transcriptomics  
Для всего что про РНК и экспрессию генов.

## ⚙️Methods
Если заметка о том КАК что-то делать (общий метод).
Не ставь если метод специфичен для конкретной области (тогда используй её тег).
```

Сейчас эти правила разбросаны по полям `summary` в самих индексных страницах — неудобно для агента и для самого пользователя.
